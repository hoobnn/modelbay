# 0006：默认模型可以按渠道分别声明

- 状态：已接受
- 日期：2026-11-19

## 背景

[0003](0003-capabilities-and-model-declarations.md) 把模型身份和渠道分开：同一个声明可以挂在多个渠道上，例如百炼按量（`bailian`）和百炼套餐（`bailian-plan`）。默认模型原先只能标在声明上（`default: true`），作用于这个声明的所有渠道和所有能力。

各平台的不同渠道上架节奏不一致。2026-11-19 统一更新默认模型时（#53），百炼按量渠道已有 `qwen4-max`，套餐渠道还只有 `qwen3.8-max`。只靠声明级标记，要么两个渠道一起换（套餐渠道就没有可用的默认模型），要么一起不换（按量渠道停在上一代）。

## 决策

- 渠道条目（`ChannelRef`）可以写 `default: true`，表示在这个渠道里，该模型是它所有能力的默认模型，称为**渠道级默认**。原来写在声明上的 `default: true` 称为**声明级默认**，含义不变：作用于它的所有渠道。
- 选默认模型时，某个「渠道 + 能力」先看渠道级默认，没有再看声明级默认，由 core 的 `selectDefaultModel()` 统一实现。两者都没有，就没有默认模型，仍然不按声明顺序兜底。
- 调用方没有传渠道时，先取声明级默认，没有再取声明顺序中第一个渠道级默认。平台有多个渠道时，调用方应当传渠道；适配器和 MCP 本来就按主渠道传。
- 约束（`validateDeclaration()` 和 `defaultConflicts()` 检查，`packages/modelbay/test/declarations.test.ts` 对全部声明执行）：
  - 渠道级默认和声明级默认一样，只能标在 `active` 模型上；
  - 同一「渠道 + 能力」最多一个渠道级默认，也最多一个声明级默认。渠道级压过声明级是预期内的优先关系，不算冲突；
  - 同一个声明不能既有声明级默认又有渠道级默认，因为两者重复。
- 粒度只到渠道，不到能力。一个声明在某个渠道上是默认，就是它在这个渠道的所有能力的默认。

## 理由

- 渠道是 0003 已有的概念，默认模型跟着渠道走，声明数据里能直接看出「这个渠道用谁」，适配器和消费方仍然不写死型号。
- 只写声明级默认的旧声明不需要改，行为完全不变，第三方扩展的声明也不受影响。
- 不按能力细分：目前没有「同一声明、同一渠道，不同能力要不同默认」的实际需要，多一层粒度只会让冲突规则更难读。真遇到时，先把这个声明按能力拆开。

## 代价与约束

- 默认模型的规则分成两层，读声明时要同时看声明上和渠道条目上的 `default`。`defaultConflicts()` 的提示会写明是哪一层冲突。
- 换默认时，如果新型号只在部分渠道上架，就给新型号写渠道级默认，同时把旧型号的声明级默认改成它所在其余渠道的渠道级默认，不要留下没有默认的渠道。
