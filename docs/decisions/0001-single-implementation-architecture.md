# 0001：一份实现覆盖多家平台，四层架构

- 状态：已接受
- 日期：2026-11-04

## 背景

火山方舟、豆包语音、阿里云百炼、MiniMax 都提供 OpenAI 兼容的对话接口，Vercel AI SDK、LiteLLM 也都能用。但视频、语音、复刻、异步任务和素材上传，各家差异很大，没有可用的开源统一实现。上游又经常改参数范围、默认值和模型状态，如果 SDK、MCP、CLI 各写一份对接代码，每次上游变化都要改好几处，说明也会不一致。

## 决策

1. Modelbay 用 TypeScript 维护这些平台（外加 OpenAI）唯一的一份实现。SDK 汇总入口、MCP、CLI 和其他应用都只是它的消费方。命名和许可见 [0002](0002-naming-license-and-namespaces.md)。
2. 分四层：

   | 层         | 包                                                                                                       | 职责                                                                                                       |
   | ---------- | -------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------- |
   | 核心运行时 | `@modelbay/core`                                                                                         | 能力类型、输入输出、错误归一化、HTTP（重试 / 超时 / 代理）、异步任务生命周期、按声明校验、素材上传策略接口 |
   | 模型声明   | 放在各平台包内                                                                                           | 纯数据，格式见 [0003](0003-capabilities-and-model-declarations.md)                                         |
   | 平台适配器 | `@modelbay/ark`、`@modelbay/bailian`、`@modelbay/minimax`、`@modelbay/doubao-speech`、`@modelbay/openai` | 只写各家不同的部分：鉴权、路由、请求和响应映射、错误码映射                                                 |
   | 消费方     | `modelbay`（汇总入口）、`@modelbay/mcp`、`@modelbay/cli`                                                 | 不包含平台逻辑                                                                                             |

3. 文本对话（`text.chat`）走 Vercel AI SDK 的 OpenAI 兼容层，不给每家写专门的对话适配。平台特有字段（思考续传、`thinking`、联网搜索、`previous_response_id`）要能原样透传，传不过去的那一家保留一层薄适配。
4. 核心通过接口注入宿主差异，并自带默认实现：
   - `JobStore`：异步任务持久化，默认存内存或本地 JSON，宿主可以换成数据库。
   - `AssetSource`：输入素材的来源，可以是路径、字节或 URL，默认读本地文件。
   - 结果只返回 URL 或字节，下载和入库由宿主负责。
   - 事件钩子：回调进度和用量（token、秒数、字符数、张数）。
5. 画布、工作流相关的部分（节点、端口、插件清单、审批）由上层应用负责，不进核心。

## 理由

- 上游变化最常见的是参数范围、默认值和新增模型。这些写成声明数据之后只改一处，表单、预检、MCP 工具 schema 都从声明派生。
- 选 TypeScript：桌面端和 Web 应用可以直接用，MCP 也能用 `npx` 分发。

## 代价与约束

- 核心必须不依赖特定运行时，只用 `fetch`、`Uint8Array` 这类各运行时都有的 API。`sharp`、`fs`、`@volcengine/tos-sdk` 这类只能在 Node 下用的依赖，放到可选子路径 `@modelbay/<平台>/node`。
- 核心接口按 semver 管理，只加字段、不改语义。
- 非 TypeScript 的消费方（其他语言、iOS 原生）以后通过 HTTP 网关接入，网关的 OpenAPI 由声明生成。第一个这类消费方出现之前不做网关。
