# 上游文档对账

每天现抓各平台的官方文档，抽取模型清单和下线信息，和模型声明双向核对：声明能不能在官方文档里对上，官方有的模型我们声明了没有。差距写成报告，进跟踪 issue；下线公告点名的模型和官方归为历史的模型直接出生命周期补丁（历史模型一律归档成 `retired`），开草稿 PR 交人审。代码在 `scripts/upstream/`，定时任务是 `.github/workflows/upstream-docs.yml`。

定时任务用本次取得的官方原文核对 `PlatformDescriptor.models`。抓取结果与报告保存在 `.upstream-docs/`，`--offline` 可按当前来源计划重放这些快照。

## 流程

1. **抓取。** 页面来自两处：`scripts/upstream/sources.ts` 里各平台的目录页（模型列表、下线公告），以及声明里引用的所有来源页。每页按档位取 Markdown，先成功的为准：

   | 档位                | 做法                                               | 适用                                 |
   | ------------------- | -------------------------------------------------- | ------------------------------------ |
   | `markdown`          | 请求带 `Accept: text/markdown`                     | MiniMax、OpenAI、火山方舟套餐页      |
   | `markdown-suffix`   | 路径后加 `.md`                                     | 阿里云帮助中心                       |
   | `embedded-markdown` | HTML 里的 `LlmsMdUrl`                              | 火山文档站                           |
   | `rendered`          | 无头浏览器渲染，正文 DOM 转 Markdown（标题、表格） | 阿里云公告页（有反爬校验，只能渲染） |

   阿里云帮助中心每轮优先请求一次 `.md`，收到 HTTP 429 后退避。登记在 `RENDER_SELECTORS` 里的站点可渲染正文。公告索引可以用 `follow` 发现详情页，并记录链接所在小节的日期。渠道缺少任一计划列表页时，该渠道的列表核对暂停，报告仍保存已抓到的页面。

2. **抽取。** 所有页面都转成同一种结构：表格行（带表头）和正文行（带标题路径），代码块不算行；HTML 标签删掉，但保留 `title` 属性（百炼总览页的模型卡片 `<Card title="…">` 只在这里写模型名）。规则对所有平台通用：
   - 行里出现的已声明 ID（渠道内 ID、官方别名、简称）就是「点名」。表头是「替代 / 迁移 / replacement / substitute」的列不算，那是推荐的新模型。
   - 日期认 `2026-9-24`、`2026年10月10日`、`Jan 6, 2027` 等写法，模型 ID 里的日期后缀不算。行里没有日期时，公告页往外找：跟进时带来的上下文日期，再到同一小节、同一批次里的日期。
   - 候选模型 ID 的前缀从已声明的 ID 自动推出（`doubao`、`qwen`、`gpt`……），不用手写清单。一个平台上一个都没声明过的系列（如百炼上的 `deepseek`、`kimi`、`glm`）因此不会被报出；要监控就写进 `sources.ts` 的 `prefixes`。
   - 前缀只取 ID 开头那段连续字母，所以带数字的系列要写 `hyper` 而不是 `hyper3d`。
   - 带厂商前缀的 `kimi/kimi-k3` 是一个完整 ID。目录中的展示别名可通过 `catalogAliases` 绑定到同一渠道的已声明 API ID，例如 `step-5-preview` 对应 `stepfun/step-5-preview`。这个映射用于对账。
   - 候选 ID 默认要带版本号（数字），免得把文档路径当成模型。有些平台的模型 ID 不带数字（OpenAI 的 `gpt-transcribe`），在 `sources.ts` 的 `digitless` 里按前缀放行。
   - 表头里的 API ID 直接参与核对。豆包语音这类「产品名 + 版本」表头另行合成候选，并优先用该列名称推断能力。产品名与已声明 ID 只差厂商前缀时，可作为同一模型的目录证据。

3. **双向核对。**

   | 方向        | 差距                       | 判断                                                                             | 自动生成                              |
   | ----------- | -------------------------- | -------------------------------------------------------------------------------- | ------------------------------------- |
   | 声明 → 官方 | 生命周期待更新             | 下线公告点名了我们的模型而声明对不上，或列表页把它归为历史模型                   | 改好的 `lifecycle` 块，附官方原文引用 |
   | 声明 → 官方 | 官方列表和来源页里都找不到 | 渠道内 ID 和别名既不在该渠道的列表页里，也不在声明自己引用的来源页里（含代码块） | 报告条目                              |
   | 官方 → 声明 | 官方有、尚未声明           | 列表页当前小节的候选 ID 不在任何声明里，也不在 `sources.ts` 的 `skipped` 里      | `--skeleton <id>` 生成声明骨架        |

   变更依据是明确的停服状态或可归属的截止日期。日期用北京时间按日比较。公告约定当天停服时，报告保留 `sunsetting`，下一日才按日期推为 `retired`。补丁引用支持最终结论的页面和原文。
   方舟公告会分别标出停止新购（EOM）与服务下线（EOS）。自动停服补丁使用 EOS 日期或明确的停服状态，公告明确只有 EOM 的 embedding 模型保留原声明供人工核对。

   **历史模型一律归档，不再支持。** 列表页把模型放在「历史模型 / 旧版 / legacy / deprecated」小节，或表格里标了「已下线」，已声明的就出补丁改成 `retired`，来源是该列表页，覆盖公告推算的 `sunsetting`；没声明的不报，也不生成骨架。同一个 ID 还出现在任一渠道当前小节的不算历史模型；替代 / 推荐列里的模型不归档；声明涉及的渠道有一个没抓到列表页，就先不归档。官方有时只是「不再对新用户开放」也放进历史小节，按同一规则归档。

   **抓取失败不产生差距。** 某条声明的来源页没抓到时，判断不了它在不在官方文档里，「官方列表和来源页里都找不到」这一类不报；列表页没抓到时，该渠道不做列表核对。避免限流把报告搞脏。

4. **出结果。** `pages.json` 记录本次计划来源的文件或失败原因，`pages/` 保存成功页面，`report.md` 写覆盖状态和差距。CI 保留这三项 14 天。`--offline` 发现旧索引少页时，会将该来源报告为缺失。任意计划页取得失败时，命令写出报告再返回非零。

   | 操作                            | 所需证据                                                                                                   |
   | ------------------------------- | ---------------------------------------------------------------------------------------------------------- |
   | 创建、更新或关闭跟踪 issue      | 所有计划来源完成。报告有差距时同步，差距清空时关闭。                                                       |
   | 自动写生命周期补丁、同步草稿 PR | 当前日期在线抓到全部计划模型清单、下线公告和跟进的公告详情。补丁随 `upstream-docs/<平台>` 分支交人工核对。 |

## 处理差距

- **补丁要对照原文核对。** 官方页面之间可能互相矛盾，拿不准就从 PR 里撤掉这条补丁，在声明里保留现状。
- **官方列表和来源页里都找不到**：核对后改生命周期或删声明。列表页漏列的模型，把写明它的 API 文档加进声明的来源，下次就能对上。本来就不会出现在官方文档里的 ID（设置里自填的自定义模型，或文档写法和接口实际返回不一致、已按接口核实过的 ID），加进 `sources.ts` 的 `unlisted` 并写注释。
- **新模型**：要支持的，用 `--skeleton <id>` 生成骨架，照原文补齐能力、上下限、默认值，再登记进 `index.ts` 的 `all`，见 [扩展指南](extending.md#新增或修改一个模型)。决定不接的，加进 `sources.ts` 的 `skipped` 并写明原因，之后不再提醒。`skipped` 按原因分组（写法变体、旧版本、能力范围外、待定）；「待定」组是还没决定接不接的，要接哪个就从清单里删掉再写声明。

## 命令

```sh
pnpm upstream:audit                                   # 全部平台：现抓、对账、写报告
pnpm upstream:audit --platform ark --apply            # 方舟在线对账，生命周期来源齐全时写入声明
pnpm upstream:audit --platform openai --skeleton gpt-6-nova   # 给未声明的模型生成骨架，附在报告里
pnpm upstream:audit --offline                         # 不联网，用 .upstream-docs/ 里上一次抓到的全文重新对账（调抽取规则时用）
pnpm check:sources                                    # 离线：每个声明的来源都是白名单里的官方 https 地址并带核对日期
```

本地第一次跑需要无头浏览器：`pnpm exec playwright install --only-shell chromium`。

`--today YYYY-MM-DD` 可按指定日期重放结论。写入声明时，`--apply` 使用当前日期和在线取得的证据。

## 新增平台或页面

在 `scripts/upstream/sources.ts` 的 `SOURCES` 里加一项：模型列表页写 `role: 'list'` 和对应的 `channel`，下线公告页写 `role: 'deprecation'`。文档域名不在 `OFFICIAL_HOST_SUFFIXES` 里的要先加进去。拿不到 Markdown、只能浏览器渲染的域名，在 `RENDER_SELECTORS` 里写正文容器的选择器。然后在工作流的平台列表里加上 `key`，本地跑一次 `pnpm upstream:audit --platform <key>` 看报告。

平台配置还可以提供以下目录识别规则。

| 字段             | 作用                                                                                    |
| ---------------- | --------------------------------------------------------------------------------------- |
| `prefixes`       | 额外的候选前缀。一个系列在平台上没声明过时，前缀自动推不出来，得在这里写                |
| `digitless`      | 模型 ID 不带版本号的前缀。默认候选规则要求 ID 带数字，免得把文档路径当模型              |
| `unlisted`       | 本来就不出现在官方文档里的 ID（自定义模型、文档写法与接口实际不一致、已按接口核实过的） |
| `catalogAliases` | 渠道内的目录展示写法与已核实的已声明 API ID 对应关系                                    |

## 以后可以加的

- **用大模型抽取自由文本公告。** 现在的规则能处理表格和带日期的行，处理不了「M2.5、M2.7 系列模型」这种按系列描述的公告。可以让模型按 JSON Schema 输出并附原文引用，没有引用的丢弃。需要在 CI 里配 key，结果也不完全确定，所以先不做。
- **参数上下限对账。** 现在只核对模型在不在、生命周期对不对，上下限和默认值的差异靠人看来源页。
