# 上游文档对账

每天现抓各平台的官方文档，抽取模型清单和下线信息，和模型声明双向核对：声明能不能在官方文档里对上，官方有的模型我们声明了没有。差距写成报告，进跟踪 issue；下线公告点名的模型和官方归为历史的模型直接出生命周期补丁（历史模型一律归档成 `retired`），开草稿 PR 交人审。代码在 `scripts/upstream/`，定时任务是 `.github/workflows/upstream-docs.yml`。

仓库里不存任何官方文档内容，也不存上一次的结果。每次都只拿这一次抓到的原文核对，结论不依赖历史状态。

## 流程

1. **抓取。** 页面来自两处：`scripts/upstream/sources.ts` 里各平台的目录页（模型列表、下线公告），以及声明里引用的所有来源页。每页按档位取 Markdown，先成功的为准：

   | 档位                | 做法                                               | 适用                                 |
   | ------------------- | -------------------------------------------------- | ------------------------------------ |
   | `markdown`          | 请求带 `Accept: text/markdown`                     | MiniMax、OpenAI、火山方舟套餐页      |
   | `markdown-suffix`   | 路径后加 `.md`                                     | 阿里云帮助中心                       |
   | `embedded-markdown` | HTML 里的 `LlmsMdUrl`                              | 火山文档站                           |
   | `rendered`          | 无头浏览器渲染，正文 DOM 转 Markdown（标题、表格） | 阿里云公告页（有反爬校验，只能渲染） |

   只有 `RENDER_SELECTORS` 里登记了正文容器的域名才会渲染。其他站点拿不到 Markdown 多半是被限流，渲染出来的是导航和校验页，所以直接算抓取失败。某个渠道的列表页有一页没抓到，这个渠道就不做列表核对，免得把漏抓当成「官方没列」。公告索引页可以配置 `follow`，继续抓页面里链到的公告详情，详情页带上链接所在小节标题里的日期。

2. **抽取。** 所有页面都转成同一种结构：表格行（带表头）和正文行（带标题路径），代码块不算行。规则对所有平台通用：
   - 行里出现的已声明 ID（渠道内 ID、官方别名、简称）就是「点名」。表头是「替代 / 迁移 / replacement / substitute」的列不算，那是推荐的新模型。
   - 日期认 `2026-9-24`、`2026年10月10日`、`Jan 6, 2027` 等写法，模型 ID 里的日期后缀不算。行里没有日期时，公告页往外找：跟进时带来的上下文日期，再到同一小节、同一批次里的日期。
   - 候选模型 ID 的前缀从已声明的 ID 自动推出（`doubao`、`qwen`、`gpt`……），不用手写清单。

3. **双向核对。**

   | 方向        | 差距                       | 判断                                                                             | 自动生成                              |
   | ----------- | -------------------------- | -------------------------------------------------------------------------------- | ------------------------------------- |
   | 声明 → 官方 | 生命周期待更新             | 下线公告点名了我们的模型而声明对不上，或列表页把它归为历史模型                   | 改好的 `lifecycle` 块，附官方原文引用 |
   | 声明 → 官方 | 官方列表和来源页里都找不到 | 渠道内 ID 和别名既不在该渠道的列表页里，也不在声明自己引用的来源页里（含代码块） | 报告条目                              |
   | 官方 → 声明 | 官方有、尚未声明           | 列表页当前小节的候选 ID 不在任何声明里                                           | `--skeleton <id>` 生成声明骨架        |

   推算的状态：公告明确写了「已下线」就是 `retired`；否则取最晚的日期，未到期是 `sunsetting` 并写 `sunsetOn`，已过期是 `retired`。

   **历史模型一律归档，不再支持。** 列表页把模型放在「历史模型 / 旧版 / legacy / deprecated」小节，或表格里标了「已下线」，已声明的就出补丁改成 `retired`，来源是该列表页，覆盖公告推算的 `sunsetting`；没声明的不报，也不生成骨架。同一个 ID 还出现在任一渠道当前小节的不算历史模型；替代 / 推荐列里的模型不归档；声明涉及的渠道有一个没抓到列表页，就先不归档。官方有时只是「不再对新用户开放」也放进历史小节，按同一规则归档。

4. **出结果。** 报告写到 `.upstream-docs/<平台>/report.md`，抓到的全文在 `.upstream-docs/<平台>/pages/`，都不进仓库，CI 作为 artifact 保留 14 天。定时任务：
   - 声明这一侧有差距，就开或更新标题为「上游文档对账：<平台>」的 issue，正文是报告，末尾 @ 仓库所有者请求处理，issue 也指派给他；之后报告有变化才更新正文并评论 @ 一次，没变化不重复提醒；差距消失后自动关掉。生命周期补丁的草稿 PR 同样指派给仓库所有者。官方有、我们没声明的模型只列在报告里，不会单独让 issue 开着。
   - 有生命周期补丁，就推到 `upstream-docs/<平台>` 分支，开或更新一个草稿 PR。

## 处理差距

- **补丁要对照原文核对。** 官方页面之间可能互相矛盾，拿不准就从 PR 里撤掉这条补丁，在声明里保留现状。
- **官方列表和来源页里都找不到**：核对后改生命周期或删声明。列表页漏列的模型，把写明它的 API 文档加进声明的来源，下次就能对上。本来就不会出现在官方文档里的 ID（设置里自填的自定义模型，或文档写法和接口实际返回不一致、已按接口核实过的 ID），加进 `sources.ts` 的 `unlisted` 并写注释。
- **新模型**：要支持的，用 `--skeleton <id>` 生成骨架，照原文补齐能力、上下限、默认值，再登记进 `index.ts` 的 `all`，见 [扩展指南](extending.md#新增或修改一个模型)。

## 命令

```sh
pnpm upstream:audit                                   # 全部平台：现抓、对账、写报告
pnpm upstream:audit --platform ark --apply            # 只跑方舟，并把生命周期补丁写进声明
pnpm upstream:audit --platform openai --skeleton gpt-6-nova   # 给未声明的模型生成骨架，附在报告里
pnpm upstream:audit --offline                         # 不联网，用 .upstream-docs/ 里上一次抓到的全文重新对账（调抽取规则时用）
pnpm check:sources                                    # 离线：每个声明的来源都是白名单里的官方 https 地址并带核对日期
```

本地第一次跑需要无头浏览器：`pnpm exec playwright install --only-shell chromium`。

## 新增平台或页面

在 `scripts/upstream/sources.ts` 的 `SOURCES` 里加一项：模型列表页写 `role: 'list'` 和对应的 `channel`，下线公告页写 `role: 'deprecation'`。文档域名不在 `OFFICIAL_HOST_SUFFIXES` 里的要先加进去。拿不到 Markdown、只能浏览器渲染的域名，在 `RENDER_SELECTORS` 里写正文容器的选择器。然后在工作流的平台列表里加上 `key`，本地跑一次 `pnpm upstream:audit --platform <key>` 看报告。

## 以后可以加的

- **用大模型抽取自由文本公告。** 现在的规则能处理表格和带日期的行，处理不了「M2.5、M2.7 系列模型」这种按系列描述的公告。可以让模型按 JSON Schema 输出并附原文引用，没有引用的丢弃。需要在 CI 里配 key，结果也不完全确定，所以先不做。
- **参数上下限对账。** 现在只核对模型在不在、生命周期对不对，上下限和默认值的差异靠人看来源页。
