# @modelbay/mcp

MCP tool generator and per-platform stdio servers for [Modelbay](../../README.md). MIT licensed.

`@modelbay/mcp` derives MCP tools from `ModelDeclaration` data and `@modelbay/core` schemas, and
serves them over a minimal stdio JSON-RPC transport. It does **not** depend on
`@modelcontextprotocol/sdk` or any other new runtime dependency.

## Commands

One command per platform. The migration order (per `docs/goals.md` M4) is
**Ark → MiniMax → Bailian → Doubao Speech**:

| Order | Platform        | Command                      | Key environment variables              |
| ----- | --------------- | ---------------------------- | -------------------------------------- |
| 1     | Volcengine Ark  | `modelbay-ark-mcp`           | `ARK_API_KEY`                          |
| 2     | MiniMax         | `modelbay-minimax-mcp`       | `MINIMAX_API_KEY`                      |
| 3     | Alibaba Bailian | `modelbay-bailian-mcp`       | `BAILIAN_API_KEY`                      |
| 4     | Doubao Speech   | `modelbay-doubao-speech-mcp` | `DOUBAO_APP_ID`, `DOUBAO_ACCESS_TOKEN` |

Keys are supplied by the host through environment variables; the SDK never stores them. When a key
is missing, `tools/list` still works and `tools/call` returns a clear error instead of crashing.

### Node-only capabilities

Some capabilities need Node-only implementations (object-storage uploads, `sharp` mask
processing). They live in the platform packages' optional subpaths and are loaded and injected
automatically at launch:

| Platform | Subpath                        | Injected option   | Capability                    |
| -------- | ------------------------------ | ----------------- | ----------------------------- |
| Ark      | `@modelbay/ark/tos`            | `uploadVideo`     | video reference upload        |
| Bailian  | `@modelbay/bailian/image-edit` | `edit`, `process` | `image.edit`, `image.process` |
| Doubao   | `@modelbay/doubao-speech/asr`  | `asr`             | streaming ASR                 |

The optional peer dependencies (`@volcengine/tos-sdk`, `sharp`, `ws`) are imported lazily inside
those subpaths, so a missing dependency never stops the server from starting — the call that needs
it fails with an explicit "install X" error instead. When a subpath cannot be loaded at all, the
adapter is created without that option and the affected capability reports which subpath to inject.

Ark's reference-video upload additionally needs the storage configuration, read from the same
environment: `ARK_REFERENCE_STORAGE` (`tos` / `oss` / `cos` / `s3`), `ARK_REFERENCE_BUCKET`,
`ARK_REFERENCE_REGION`, and optionally `ARK_REFERENCE_ENDPOINT` and `ARK_REFERENCE_PATH_STYLE`,
plus the key pair `ARK_TOS_ACCESS_KEY` / `ARK_TOS_SECRET_KEY`. These are optional: without them the
server still starts and only the video-reference path is unavailable.

## Tool groups

`MODELBAY_MCP_GROUPS` (comma separated) controls which groups are exposed by `tools/list`:

| Group        | Default | Contents                                                                  |
| ------------ | ------- | ------------------------------------------------------------------------- |
| `core`       | yes     | generation, query and local/introspection tools                           |
| `realtime`   | no      | realtime session open/send/receive/close                                  |
| `management` | no      | console, hotword tables, task deletion, raw request                       |
| `node`       | no      | capabilities that require the optional `node:` subpath (e.g. file upload) |

Example: `MODELBAY_MCP_GROUPS=core,realtime modelbay-doubao-speech-mcp`.

## How tools are generated

- `docs/inventory/mcp-*.json` is the **minimum baseline** (70 tools: Ark 9, MiniMax 18, Bailian 19,
  Doubao Speech 24). The data lives in `src/catalog/` (generated by `scripts/gen-catalog.mjs`).
- The **model parameter part** of each `inputSchema` — model ID, capability params, limits,
  defaults and lifecycle notices — is derived at runtime from `ModelDeclaration` plus
  `capabilityInputSchema()` / `declarationJsonSchema()` / `selectDefaultModel()` /
  `lifecycleNotice()` from `@modelbay/core`. Nothing is hardcoded in code (hard rule from `AGENTS.md`).
- Platform-specific fields come from the catalog baseline schema. The derived `model` field overrides
  the baseline placeholder default; declaration option properties are merged additively so baseline
  field types stay consistent.
- `annotations` are **re-derived** from capability metadata (`ToolNature`), not copied from the
  baseline (some baseline entries miss `destructiveHint`).
- Cross-platform tool names are unified; MiniMax legacy names (`text_to_audio`, `text_to_image`,
  `voice_clone`, `voice_design`) are kept and additionally exposed under unified aliases. See
  `docs/mcp-tool-diff.md` for every tool beyond the baseline and the `voice.list` naming note.

## JSON-RPC methods

`initialize`, `ping`, `tools/list`, `tools/call`; plus `resources/list`,
`resources/templates/list`, `prompts/list` (empty, protocol completeness). Framing supports both
newline-delimited JSON (MCP stdio standard) and `Content-Length` headers. Responses use the same
framing as the request. All logs go to **stderr** so stdout is never polluted.

`tools/call` routes to `PlatformAdapter.submit` (normalized capabilities) or
`PlatformAdapter.native` (single-platform ops); local introspection tools are answered in-process.

## Programmatic use

```ts
import { generateTools, listTools, createServer, createHandlers, MCP_TOOL_GROUPS } from '@modelbay/mcp'

const set = generateTools('ark', { adapter: arkAdapter })
const tools = listTools(set, MCP_TOOL_GROUPS.all) // full parity with the baseline
```

## Testing

`vp test run packages/mcp` runs the baseline parity tests, a real stdio smoke test (child process +
pipes), and unit tests for catalog parsing, schema derivation, group switches, routing and error
paths. See `docs/mcp-tool-diff.md` for the per-platform tool comparison.
